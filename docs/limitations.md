# Known limitations

- The bundled wake-word models are English. Other wake words need a custom model.
- Wake-word model licenses are CC BY-NC-SA 4.0: non-commercial use only.
- The built-in intent parser is configured for one language. Other languages rely on Home Assistant or the local model for those intents.
- Recognition accuracy depends on the model and the language. A larger model is more accurate and slower.
- The wake-word threshold is one server value for all clients.
- The end of speech uses a fixed level, not a voice detector. Steady noise can keep the recording open until `VOICE_RECORD_MAX`.
- A command spoken immediately after the wake word can lose its first syllable. Pause briefly after the wake word.
- Device names must contain only letters, digits and spaces. Other names are left out with a warning.
- Device suffixes follow the system device order. Reconnecting a device can change which suffix points to which device.
- After an audio device disconnects, the client does not reopen it. Restart the assistant.
- The output keepalive holds the speaker that was selected at startup, so changing the output device needs an assistant restart. Set `VOICE_KEEP_OUTPUT_AWAKE=false` to let the device sleep, for example with battery-powered headphones; an idle Bluetooth sink can then swallow the beep.
- Diagnostic tail recordings contain microphone audio from just after a reply or just before a wake-word detection, so they can include nearby private speech. They are off by default; when `VOICE_TAIL_DIR` is set, the client keeps only the newest `VOICE_TAIL_KEEP` files with mode `0600` in that directory.
- The wake-word high-pass (`VOICE_WAKEWORD_HIGHPASS`) filters only the audio sent to openWakeWord; command recordings, speech recognition and tails keep the raw microphone signal. Lower it or set it to `0` if the wake word stops being detected.
- The local model can choose the wrong exposed device or answer incorrectly. Use `VOICE_LLM_SAFETY=guard`, unexpose devices it must not control, or disable it with `VOICE_LLM_MODE=off`.
- The model has no internet access or conversation state. General answers use its own knowledge; state answers use the snapshot it receives.
- Prompt changes apply when the assistant restarts.
- Learning matches the whole normalized sentence, so a rephrasing is a new entry. Negative feedback applies only to the last local action within 60 seconds.
- The dashboard Learning view mirrors the client memory, but edits and deletions are queued for the client rather than applied on the dashboard only. They reach the store when the client polls, a few seconds while it runs, and stay pending while it is stopped or publishing is disabled.
- The dashboard cannot verify that an action or device still exists when an association is created or edited. The client checks the target at run time, like an automatically learned entry.
- A manual association is keyed by its normalized sentence. Creating one with the same sentence as an existing association is rejected; editing the sentence moves the association to the new key.
- Learned phrases and queued edits are recognized speech and can contain private information. The dashboard stores both the snapshot and the operation queue with mode `0600`, but its Learning API and page have no authentication, and the write endpoints are reachable wherever the dashboard is bound.
- The room comes from `VOICE_ROOM` and matches device names, not Home Assistant areas.
- The catalog changes at most every 30 seconds after an entity changes.
- The dashboard action list is a read-only preview generated by the collector from the Home Assistant exposure settings. It requires `VOICE_HA_URL` and `VOICE_HA_TOKEN` in `server/.env`, which must point to the same Home Assistant as the client. It shows only the deterministic catalog, not built-in intents or learned associations.
- The Home Assistant conversation fallback is stateless and does not support follow-up questions.
- Domains or features without a catalog generator (for example climate setpoints or TV channels) rely on the Home Assistant conversation agent.
- The development Home Assistant stores its login and token in plain files. Use it only for development.
- The dashboard has no authentication and is meant for localhost use. If `BIND_ADDRESS` is changed to a wider interface, service metadata, container logs and learned phrases become reachable on that network.
- The dashboard collector mounts the Docker socket read-only, but the Docker API itself is not read-only. The collector makes allowlisted `GET` calls and one scoped `POST` to restart a monitored compose service; treat the socket mount as a root-equivalent capability and keep the collector internal. The dashboard cannot restart itself from the Services page.
- Dashboard notifications are derived from observed container transitions. Read state lives in the browser, so it is per browser profile, resets with site data, and is not a durable audit log.
- Settings overrides live in the `dashboard-data` volume, not in the `.env` files. Server and shared changes apply with `make services-up`; client changes apply when `make run` restarts. The settings endpoints can return the Home Assistant token, so keep the dashboard on localhost or a trusted network.
- Container logs do not carry a severity field. The dashboard infers `info`, `warn`, `error` and `debug` from the message text; the badge is a filter aid, not an authoritative level.
- Dashboard status is served from a background snapshot refreshed every 2 seconds, so it can be up to about 2 seconds old. This keeps requests fast and avoids blocking on Docker stats.
- Service counts and container memory/CPU metrics cover Docker containers only. Home Assistant is reported as a separate source and is not part of those totals. The development Home Assistant started by `make ha-up` is not listed as a service.
- Host uptime is available only when `VOICE_HA_URL` and `VOICE_HA_TOKEN` are set and Home Assistant exposes a System Monitor last-boot or uptime sensor. Otherwise it shows `—`.
- The dashboard log view covers containers only. It does not read the assistant transcript log, which stays off unless `VOICE_LOG_TRANSCRIPTS` is enabled.
