# Known limitations

- Wake word: there is no Spanish wake-word model in the image. The five built-in models (`okay_nabu`, `hey_jarvis`, `hey_mycroft`, `alexa`, `hey_rhasspy`) are English. The PoC uses `alexa` with the spoken word "Alexa" (see [wake-word.md](wake-word.md)), so "Alex" and "Alexis" also wake it. An Amazon Echo near the microphone can also react. A custom model needs separate training and a `--custom-model-dir` mount.
- Wake-word model license is CC BY-NC-SA 4.0: non-commercial use only.
- openWakeWord ignores an unknown `--preload-model` name with no error, so the compose file does not preload a model. The client gives the model name in each `detect` event.
- Whisper `base` is weak on short Spanish phrases. "¿Qué hora es?" from Piper gave "que hora es", "que ahora es", "¡Qué oras!" and "¡Qué odes!" in different runs. A larger model (`small`, `medium`) is more accurate but slower. Measure on the real hardware before you change it.
- Piper engine is GPL-3.0. It runs in a separate container and the client talks to it over the network only.
- Piper `describe` lists all known voices, also voices that are not on disk. Piper downloads a requested voice on the first `synthesize`. `scripts/verify.sh` checks that the voice is listed, not that it is on disk.
- Whisper needs the client to detect the end of speech (no server VAD).
- The wake-word threshold is one server value for all clients (`WAKEWORD_THRESHOLD`). The Wyoming `detect` event has no threshold field, and `detection` has no score.
- The wake-word integration test uses synthesized English speech. Real voices, accents and rooms need the manual test procedure in [wake-word.md](wake-word.md).
- Device suffixes (` #2`) follow the order of the system device list. If that order changes (for example after a reconnect), a suffix can point to the other device.
- Device disconnection was not tested with real hardware. The unit tests cover the error path of the ring buffer only.
- After a device disconnects, the client does not reopen it. The pipeline phases must decide how to recover.
- In `run` and `stt-test`, the wake-word stream reads the microphone until the detection arrives (about 100 to 200 ms after the wake word). A command said with no pause after "Alexa" can lose its first syllable. Make a short pause after the wake word.
- The end of speech is found with a fixed level (`--speech-level`), not with a voice detector. Loud steady noise (a fan near the microphone) counts as speech and keeps the recording open until `--record-max`.
- Device names are not in `WHISPER_INITIAL_PROMPT`, because the prompt is a fixed server setting and the devices come from Home Assistant. "Enciende la luz de la cocina" was recognized correctly in the end-to-end test; unusual device names can be recognized worse. Add the phrases of your devices to `WHISPER_INITIAL_PROMPT` if necessary.
- A device name must have only letters, digits and spaces (for example not "Luz + LED"). A device with another name is left out, with a warning in the log.
- The fixed parser no longer matches device names. A device sentence is resolved by learned memory, Home Assistant or the language model, and `guard` only accepts the model's device when the sentence clearly names it. Use the full device name; Home Assistant aliases and areas are used only by the conversation fallback.
- The language model is a 0.5B model and can still choose the wrong action, device, or reply. It runs for any unresolved sentence that is not in learned memory, with the default `ha-first` order after Home Assistant. For actions it gets the action catalog and runs the inferred actions in the requested order, without a confirmation, so a wrong inference can act on the wrong exposed device. The default `guard` safety discards an action for chat or a device that the sentence does not clearly name, and accepts a physical state only when the chosen device can fix it; `literal` runs any action, and `states` only physical states. The catalog limits this to actions of exposed entities, but it includes locks, covers, valves, scenes, scripts and climate when they are exposed; the guard and its verb rule reduce the risk. Unexpose a device that the local model must not control. For questions it also gets up to 50 exposed entities and 4 forecast entries, so it can answer "¿Va a llover?" only when the exposed weather forecast contains the answer; if the weather entity is not exposed, the forecast call fails, or the model misreads the data, it returns no reply. The 0.5B model can also echo the question or answer from the wrong row; the handler rejects an echo, punctuation-only reply, or a reply without context, but a plausible wrong answer can still be spoken. Check `msg=reasoned` for an accepted action/reply and `reasoned rejected` at debug level for a discarded one. Fetching the snapshot adds Home Assistant requests, and a context prompt is larger than a command prompt; a context question can exceed the default 30 s `VOICE_LLM_TIMEOUT`, especially on a small CPU. `model-first` adds that latency before Home Assistant.
- Learning matches the whole normalized sentence, so a rephrasing is a new entry. A positive learned sentence does not run the model or Home Assistant; a punished sentence skips the local action, and with `ha-first` it can still be sent to Home Assistant. "Mal" only refers to the last local action within 60 seconds and does not undo the action already sent to Home Assistant. A punished entry is dropped, but if the model insists on the same action the assistant refuses to run it and says it does not know; rephrase the sentence or name the device. A sentence handled by the Home Assistant conversation agent is not learned and cannot be punished with "mal"; a model reply is not learned either, because its source can change.
- The room comes from `VOICE_ROOM` and is matched against the device names, not from Home Assistant areas. If your devices are not named after their room ("la luz del salón"), the model may pick another device and the assistant will act on the wrong one.
- The fixed parser only splits fixed commands on "y" or "e"; it does not split device sentences. Say one local device action per sentence. When the sentence goes to Home Assistant, its agent decides how many actions it understands.
- The local catalog covers the domains with a generator in `client/internal/actions/actions.go` and a service in its allowlist. A domain or feature without a generator (climate setpoints, TV channels, a preset that is not in `preset_modes`, a select option that is not exposed, and so on) is not in the catalog; the sentence goes to the Home Assistant conversation agent, which must be configured, understand Spanish, and support it. The default `home_assistant` agent supports the common built-in intents; an LLM agent supports more. If the agent is cloud-based, the sentence leaves your network. Questions may instead be answered by the local model from the read-only snapshot.
- The deterministic catalog match is conservative. It requires a known verb and a unique entity; a phrase with a number or a parameter ("pon el aire a 22 grados", "sube el volumen al 50"), a mode word ("modo", "calor", "frio"), an unknown verb, or two matching actions goes to Home Assistant or the model. The model's choice is then checked by the guard. A wrong model choice on an exposed entity is still possible; check `msg=reasoned`.
- The catalog is regenerated at start and when the last read is older than 30 s. A new, removed or unavailable entity can take up to 30 s to change the local actions. The JSON file written by `voice-client actions` is a snapshot for inspection; the assistant does not read it at runtime.
- The Home Assistant conversation fallback is stateless: it does not keep `conversation_id`, so a follow-up that depends on the previous question is not supported. It also does not log the action in `msg=action`; check the Home Assistant log for that.
- The language model does not keep a conversation: each sentence is independent, the context snapshot is fetched fresh, and `repeat` returns the previous transcript, not a chat answer.
- The development Home Assistant is for development only: its login and token are in plain files in `server/homeassistant`.
