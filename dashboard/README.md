# M4nhattan dashboard

Next.js dashboard for the M4nhattan services. Service, resource, activity, log,
notification, action and learned-association data is live; prompt and
configuration overrides are stored on the host.

## Run

From the repository root:

```sh
make services-up
```

Open http://127.0.0.1:3005.

## Live data

The dashboard does not mount the Docker socket. A collector service
(`collector/`, added to `server/compose.yaml`) is the only component with the
socket. It exposes an internal JSON API on port 8090 with no published port.
The dashboard proxies it through server-side route handlers, so the browser
only calls the same origin:

| Route | Purpose |
|---|---|
| `GET /api/status` | Services, memory, CPU, activity and derived notifications |
| `GET /api/logs` | Container logs with a cursor and `service`/`level` filters |
| `GET /api/actions` | Action catalog generated from the exposed Home Assistant entities |
| `POST /api/services/restart` | Restarts one monitored compose service by id |
| `GET /api/learning` | Last learned-association snapshot plus queued edits |
| `POST /api/learning` | Receives a learned-association snapshot from the voice client |
| `GET /api/learning/operations` | Returns queued edits after an id for the voice client |
| `POST /api/learning/operations` | Queues a create, edit or delete from the Learning page |

The pages poll `api/status` every 5 seconds, `api/logs` every 2 seconds,
`api/actions` every 15 seconds and `api/learning` every 30 seconds, or every 5
seconds while edits are waiting for the client. Polling pauses while the page is
hidden and backs off after failures. When the collector is unreachable the UI
shows an honest error or stale state; it never falls back to sample data.

The collector refreshes its snapshot in the background every 2 seconds and
serves that cached copy, so status responses stay fast and do not wait on the
Docker API. If Docker is temporarily unavailable, it serves the last good
snapshot with the Docker source marked unavailable.

The action catalog is refreshed every 30 seconds from the Home Assistant
exposure settings and entity states. The collector keeps the last good catalog
when Home Assistant is unreachable, so the Actions page can show a stale state
instead of an empty list. The catalog follows the same rules as the client's
in-memory catalog, but it is generated by the collector and does not include
built-in intents or learned associations.

The play button on each row runs that action now through
`POST /api/actions`. Only the action ID is sent; the collector resolves it
against its own catalog and calls the fixed Home Assistant service, so the
browser cannot run an arbitrary service.

## Learning

The Learning page is not served by the collector. The voice client publishes a
snapshot to `POST /api/learning` through `VOICE_LEARNING_URL` (default
`http://127.0.0.1:3005/api/learning`) at startup, after a change, after applying
a queued edit and every 60 seconds. The dashboard stores the payload in
`/data/learning.json` inside the `dashboard-data` volume with mode `0600` and
serves it at `GET /api/learning`.

`GET /api/learning` adds a `source`: `ok` when the last publish is recent,
`degraded` after 5 minutes without a heartbeat, and `unavailable` when no
snapshot exists. It validates the schema and rejects oversized or malformed
payloads. It also merges the pending edit queue over the snapshot, so the page
shows queued changes immediately, and reports `pendingOperations` and
`pendingSince`.

The Learning page can create, edit, copy and delete associations, including
bulk deletion from the selection toolbar. Changes go to
`POST /api/learning/operations` and are stored in
`/data/learning-operations.json` with mode `0600`. The voice client polls
`GET /api/learning/operations?after=<id>` every 2 seconds, applies each change
to its local store and publishes a snapshot with `appliedThrough`. The dashboard
then removes the acknowledged operations. The client owns the store, so queued
changes remain pending while it is stopped, and the dashboard cannot verify that
a target still exists in Home Assistant.

The phrases are recognized speech, so keep the dashboard on localhost or a
trusted network. The Learning API and page have no authentication.

Set `COLLECTOR_URL` to change the collector address (default
`http://collector:8090`). The collector reads `VOICE_HA_URL` and
`VOICE_HA_TOKEN` when they are set in `server/.env`; otherwise the Home
Assistant card is offline, the action catalog is disabled and host uptime is
unavailable. Keep these values aligned with `client/.env` so the dashboard
catalog matches the running assistant.

The collector runs as a non-root user and needs the Docker socket group id.
`make services-up` detects it automatically. For a direct compose call, set
`DOCKER_SOCKET_GID` (for example `stat -c '%g' /var/run/docker.sock`). Compose
also adds group 0 because Docker Desktop exposes the mounted socket as
`root:root` inside the container.

Notifications are derived from container transitions. Read state is stored in
the browser, so it is per browser profile and is not an audit log.

## Dashboard only

```sh
make dashboard-up
make dashboard-down
make dashboard-logs
```

Or from this directory:

```sh
docker compose up -d --build
```

The standalone `dashboard/compose.yaml` does not include the collector. The UI
still loads, but the live data routes report the collector as unavailable.

## Settings

Open http://127.0.0.1:3005/settings to edit the language model prompt and the
per-section configuration overrides. Saved overrides live in
`/data/settings.json` inside the `dashboard-data` volume with mode `0600`, not in
the `.env` files: an empty field keeps using `server/.env` or `client/.env`.

Server and shared overrides are exported by `GET /api/settings/compose`.
`make services-up` fetches and exports them before `docker compose`, so they win
over `server/.env`; run it after saving. Client overrides are served by
`GET /api/settings/client` and read by the assistant at startup through
`VOICE_SETTINGS_URL`; the model endpoint is polled and applies within 30
seconds, while other client overrides need a `make run` restart. If the dashboard is
unreachable, both fall back to the `.env` files.

The **Model endpoint** panel only requires the endpoint URL. The model name is
optional: when it is empty, `Connect model` reads `/v1/models` and stores the
first model reported by the endpoint. A **Use local model** button fills the
local llama.cpp URL and model. The API key is optional and write-only. The
client applies a successful change within 30 seconds without a restart.

The prompt is stored separately in `/data/prompt.json` and served at
`/api/settings/prompt`. The client reads it at startup through
`VOICE_PROMPT_URL` (default `http://127.0.0.1:3005/api/settings/prompt`). The
editor shows the built-in prompt when no custom prompt is saved; `Reset to
built-in` removes the custom prompt. `{{context}}` is replaced with the read-only
Home Assistant context.

## Settings API

`GET /api/settings` returns `{ "values": { ... } }` with the saved overrides.
`POST /api/settings` takes the same shape, validates every key against the
schema, and returns the saved values. Empty values are removed. `GET
/api/settings/client` returns only the shared and client keys, and `GET
/api/settings/compose` returns shell exports for the server and shared keys.

`GET /api/settings/prompt` returns `{ "prompt": "..." }` with the saved prompt,
or an empty string when no custom prompt is saved. `POST /api/settings/prompt`
takes `{ "prompt": "..." }` and returns the saved text in the same shape.
Errors return `{ "error": "..." }`, and `prompt` is limited to 20000
characters.

The prompt is stored as `{ "prompt": "..." }` in `/data/prompt.json` inside the
`dashboard-data` volume. `Reset to built-in` saves an empty prompt, which removes
the custom prompt and falls back to the built-in prompt.

## Configuration

- `DASHBOARD_PORT`: published port (default `3005`).
- `COLLECTOR_URL`: collector address used by the server-side route handlers.
- `DOCKER_SOCKET_GID`: host Docker socket group id for the collector.
- `VOICE_HA_URL`, `VOICE_HA_TOKEN`: Home Assistant source for status, host uptime and the action catalog.
- `VOICE_LEARNING_URL`: client setting that publishes the Learning snapshot and polls the edit queue at `<url>/operations`; `off` disables both.
